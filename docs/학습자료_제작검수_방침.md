# 학습자료 제작·검수 방침

이 문서는 영어교육론·영어학 챕터 학습자료의 공통 제작 기준이다. 저장소의 [AGENTS.md](../AGENTS.md), [한글용어](한글용어.md), [기출맥락 정리](기출맥락_2010_2026.md)를 함께 따른다. 이 문서와 저장소의 기존 방침이 다르면 기존 방침의 적용 범위를 우선하고, 사용자 요청이 범위를 더 좁히면 이번 작업 범위에 맞춘다.

## 목표와 작업 범위

- 기출위키 학습자료만으로 초보자가 **이론 이해 → 개념 정리 → 실제 기출 해결 → 조건을 바꾼 문제에 적용**하도록 돕는다.
- 영어교육론 허브의 실제 챕터 순서를 먼저 확인한다. 영어교육론에서 영어학 기본, 영어학 심화·TG 순으로 한 챕터씩 진행하며, 한 챕터의 내용·UI·실제 화면 검수를 마친 뒤 다음 챕터로 넘어간다.
- 기존 요약이 정확하고 잘 정리되어 있으면 보존한다. 요청된 챕터와 파일만 수정하고, 인접 챕터나 전역 UI까지 임의로 확장하지 않는다.
- 큰 구조 변경은 먼저 대표 영역 하나에 적용해 실제 화면으로 살핀다. 확인된 방식을 나머지 해당 챕터에 확장하는 것은 작업 제안으로 기록하고, 이미 합의된 범위 안에서 진행한다.

## 자료 확인과 출처

1. 작업 전 저장소 방침과 챕터 구조, 현재 작업물, 참조 파일을 확인한다. `testmaster` 등 다른 저장 위치에는 GitHub 용량 제한으로 빠진 PDF·이미지 원문이 있을 수 있으므로 가능한 범위에서 함께 찾는다.
2. 이론 주장은 해당 개념의 원서·학술 논문 등 1차 자료와 대조한다. 기존 요약, refs, 기출 해설이 맞다고 미리 가정하지 않는다. 기출 사실은 실제 문항 원문을 확인한다.
3. 자료를 판단에 사용하는 것과 공개 출처로 표시하는 것을 구분한다. 강사 교재, 수험생·합격자 노트 등 2차 자료는 내부 비교용으로만 보고, 그것만으로 확인한 주장을 원서가 뒷받침한 것처럼 적지 않는다. 공개 참고문헌에는 실제 열람·대조한 원서나 1차 자료만 싣는다.
   공개 참고문헌은 저자·서명·판·장·쪽수의 서지 텍스트로 표시한다. 책의 PDF·스캔·전자책 파일, 원문 다운로드, Drive 등 파일 공유 링크는 공개 페이지에 올리지 않는다. 검증용으로 열람한 책 파일도 공개 링크에 연결하지 않는다.
4. 출처가 확인되지 않은 연도, 문항 번호, 연구 결과, 빈출 순위는 본문에서 단정하지 않는다. 확인이 부족한 설명은 범위를 한정하거나 생략한다.
5. 원문을 복사하거나 이름만 바꾼 예문을 만들지 않는다. 이론은 한국어로 독자적으로 설명하고, 새 예문은 목표 개념을 실제로 구분하는지와 문법·의미가 자연스러운지 확인한다.
6. 출처와 공개 본문에서 강사·수험생 자료의 이름, 문구, 이미지나 내부 검수 지시를 노출하지 않는다. 내부 검토 기록은 공개 학습 페이지에 넣지 않는다.

## 자세히 보기와 학습 설명

- 자세히 보기의 설명은 바로 위 요약·표·그림의 항목, 용어, 관계, 화살표가 뜻하는 바를 풀어준다. 위쪽보다 짧은 재요약이나 자료와 무관한 장문 에세이를 붙이지 않는다.
- 초보자가 막힐 만한 선행 개념과 판단 단서를 필요한 만큼 설명한다. 해당 개념의 이해에 필요한 방식으로 설명하며, 실제 기출을 제시하는 경우에만 문항 단서와 개념 판단을 짧게 연결한다. 조건 변경 연습은 필요한 경우에 추가한다.
- 설명 방식은 내용에 맞춰 고른다. 개념 관계는 마인드맵, 변화는 흐름도, 혼동은 비교, 추상 이론은 구체적인 예, 영어학 개념은 예문 대조를 사용한다. 모든 토글에 같은 틀을 강제하지 않는다.
- 긴 설명은 소제목, 짧은 문단, 표와 의미 있는 강조로 나눈다. 강조한 부분만 훑어도 핵심 판단 단서가 보이도록 한다.

## 기출 표시와 링크

- 실제 원문을 확인한 문항만 사용한다. 옆의 짧은 빨간 연도 배지는 `26 · 24 · 18`처럼 표시하고, 해당 챕터에서 보여 준 각 문항에는 별도로 `출처: 2024학년도 전공 A 2번`처럼 학년도·시험 구분·번호를 적어 원문에 연결한다. 기출을 설명하는 개별 문단·포인트마다 그 설명 바로 옆에 짧은 연도 배지를 둔다. 개념 단위의 출제 연도 묶음만으로 개별 문항의 출제 표시를 대신하지 않는다.
- 과거 문항에 근거 없이 전공 A/B를 붙이지 않는다. X·S·N 등 내부 데이터 식별자는 href·id 같은 연결용으로 유지할 수 있으나 학생에게 보이는 제목, 버튼, 배지와 설명에는 노출하지 않는다.
- 문항을 제시하지 않은 채 선택지 기호나 보기 조합만 답의 근거로 제시하지 않는다. 이론 설명에는 확인된 출제 포인트를 사용하고, 전체 문항 해설은 기존 해설로 연결한다.
- 개별 문항 설명에는 각각 연도·시험 구분·번호와 원문 링크를 남기고, 개념 단위의 연도 요약 행에서는 같은 학년도를 한 번만 표시한다. 출제 빈도나 순위를 말하려면 전체 범위와 산출 근거를 확인한다. 그렇지 않으면 순위 표현을 쓰지 않는다.

## 시각 강조와 별도 OX 퀴즈

- 기존 자료의 색상 체계를 유지한다. refs·기출에서 확인한 중요도에 따라 개념 정의의 핵심 구절을 선별해 밑줄·굵기·색상·연한 하이라이트로 강조한다. 실제 기출의 출제 단서는 영어·한국어 기본 정의와 자세히 보기에도 역으로 반영해 핵심 판단을 드러낸다. 이미 색상이나 배경으로 강조된 구절에는 필요한 경우 밑줄 정도만 추가하며, 같은 구절에 빨강·굵게·밑줄·형광펜을 일률적으로 모두 중첩하지 않는다. 보충 설명은 기본색으로 두고 본문 전체보다 핵심이 먼저 보이게 한다. 용어 라벨만 강조하지 말고 정의·설명 본문에서 개념을 가르는 구절을 확인한다.
- 한국어 설명과 실제 기출 예문에도 판단에 필요한 핵심 표현을 강조할 수 있다. 문단 전체를 칠하거나 밑줄 긋지 않는다. 밑줄은 편집자가 추가한 학습 단서임을 필요한 경우 짧게 안내해 원문 자체의 밑줄과 혼동을 막는다.
- 개념정리 본문에는 OX 코너나 참·거짓 문항을 넣지 않는다. 개념 설명·예문과 사례 비교·기출 연계는 본문에 유지하고, 점검 문항은 기존 별도 OX 퀴즈 페이지와 메뉴에서 제공한다.
- 개념정리용으로 이미 만든 OX 문항을 옮길 때에는 기존 단원의 OX 데이터 형식과 정답·해설 형식을 보존한다. 문항의 개념 정확성을 다시 확인하고, 기존 퀴즈와 중복되지 않는 항목만 옮긴다. 개념 본문과 퀴즈 양쪽에 같은 문항을 중복 표시하지 않는다.
- 기존 OX 퀴즈에서는 답과 근거를 처음에 접어 두고, 사용자가 답 확인을 누른 뒤 표시한다. 다시 접히는지 확인한다.

## 주제 탐색과 링크

- 실제 기출 연결, 개념 용어 연결, 허브·챕터 간 이동은 설명 자체를 대체하지 않는다. 개념사전은 본문 속 해당 키워드 자체를 클릭하면 정확한 항목으로 이동하게 연결한다. 설명 아래에 별도 ‘개념사전 연결’ 목록을 반복하지 않는다. 목차·펼침 버튼 안에는 링크를 넣지 않고, 본문에서 용어 링크와 펼침 동작을 분리한다.
- 빈출 주제를 다룰 때에는 개념 안에 관련 설명을 접어둘 수 있으며, 허브·영역별 목록의 연결이 있다면 같은 주제로 이어지도록 확인한다. 노란 테두리와 빨간 제목을 사용한다.
- “그림으로 보기”는 영어학 허브의 시각자료로 연결하고, 해당 챕터와 함께 확장한다.
- 복귀 링크가 원래 위치로 돌아가는지, 해시 주소가 해당 영역을 펼치는지, 펼침 상태가 `aria-expanded`와 일치하는지 확인한다.

## 상단 요약의 기출 표시

- 상단 ‘기출분석 포인트’에도 해당 항목 바로 옆에 검증된 짧은 빨간 연도 링크를 둔다. 본문 아래에만 연도를 넣어 상단 요약에서 출제 이력이 빠지지 않게 한다.
- ‘출제 이력 표기’처럼 표시 방법을 설명하는 별도 안내 상자는 만들지 않는다. 실제 연도 링크 자체로 정보를 전달한다.
- 연도 확인이 안 된 항목에 임의의 숫자를 붙이지 않는다. 레이아웃을 맞추려고 원래 문구에 불필요한 접두어를 추가하지 않는다.

## UI와 접근성 검수

- 챕터 범위에 한정해 글자 크기, 줄간격, 여백, 표, SVG, 화살표, 토글, 링크와 색상 대비를 점검한다. 전역 CSS를 무작정 바꾸지 않는다.
- PC와 320px, 390px, 768px 폭에서 실제 페이지를 연다. 문장과 강조가 읽히는지, 표가 의미를 보존하며 재배치되는지, 필요한 가로 스크롤이 분명한지, SVG 화살표와 연결이 온전한지, 제목 줄바꿈과 토글이 자연스러운지 확인한다.
- 가로 넘침이 없다는 사실만으로 가독성을 통과시키지 않는다. 화면 캡처와 실제 펼친 상태를 보고 텍스트 잘림, 겹침, 글자 깨짐, 뜻을 바꾸는 줄바꿈을 확인한다.
- 링크와 펼침 컨트롤을 키보드로 실행한다. 버튼 안에 또 다른 링크를 넣지 않고, 포커스 표시와 링크의 독립 동작을 확인한다. hash 이동 뒤 펼침 상태와 ARIA 상태가 맞는지 확인한다.

- 모바일 카드형 표에서는 `caption`의 너비와 줄바꿈도 직접 확인한다. `table`만 block으로 바꾸고 caption을 table-caption으로 남겨 한 글자 폭이 되지 않게 한다.
- 단일 열로 바뀌는 grid의 전체 폭 카드에는 고정 열 번호가 암묵적 추가 열을 만들지 않는지 확인한다. 전체 폭을 의도하면 명시적 grid의 끝선까지 차지하도록 설계한다.
- 짧은 개념명이 강조 상자 중간에서 어색하게 갈라지지 않도록 확인한다. 묶음 처리는 긴 용어의 화면 넘침까지 검사한 뒤 해당 범위에만 적용한다.

## 완료 기록 체크리스트

- [ ] 저장소 방침, 허브의 실제 챕터 순서, 수정 범위 확인
- [ ] refs와 누락된 원문 자료를 탐색하고, 필요한 1차 자료·실제 기출 원문 대조
- [ ] 원서 근거와 기출 근거를 분리하고, 미검증 주장을 제한하거나 생략
- [ ] 자세히 보기에서 위 요약·도식의 관계를 내용에 맞게 풀고, 실제 기출을 제시한 경우 문항 단서와 개념 판단을 짧게 연결
- [ ] 조건 변경 연습은 개념 이해에 도움이 되는 경우에 추가했는지 점검
- [ ] 연도·시험 구분·번호·원문 링크 정확성, 개별 기출 설명 바로 옆의 연도 배지, 화면상 내부 식별자 노출 여부 확인
- [ ] 기출 단서를 반영한 한국어·영어 정의와 자세히 보기 강조를 개념 중요도에 맞춰 점검하고, 중요 개념·기억 요지 강조도 규칙에 맞게 확인
- [ ] 개념정리 본문에 OX 문항이 없는지 확인하고, 옮긴 문항이 있다면 기존 OX 형식·정답·해설을 보존했으며 정확하고 중복되지 않는지 확인
- [ ] 별도 OX 퀴즈의 답 숨김·열기·다시 접기를 확인
- [ ] PC, 320px, 390px, 768px에서 표·SVG·줄바꿈·잘림·겹침을 실제 화면으로 확인
- [ ] 링크·토글의 키보드 동작, 포커스 표시, 해시 이동·복귀 동작 확인
- [ ] 수정한 내용, 확인한 자료, 실제 검수 범위, 아직 확인하지 못한 부분을 나누어 기록
- [ ] 다음 챕터·다른 파일 수정·공개 배포는 요청된 범위와 승인에 맞춰 별도로 진행

후속 UI 아이디어 중 태블릿의 문제·해설 좌우 배치, 휴대폰·태블릿별 풀이 화면, 필기와 오답노트 연결은 TODO로 남긴다. 별도 요청 전에는 현재 챕터 검수 범위에 포함하지 않는다.

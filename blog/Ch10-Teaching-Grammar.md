# Ch.10 Teaching Grammar — 문법 지도 완전 정복 | 임용영어 개념 정리

---

## ① 개념 정의

### Focus on FormS vs Focus on Form vs Focus on Meaning — 3-way 구분

문법 교수를 이해하는 핵심 틀은 이 세 가지 접근법의 차이다. 임용에서 가장 자주 뒤집어 출제하는 부분이기도 하다.

| | <span style="color:#3182ce">**Focus on FormS (FonFS)**</span> | <span style="color:#3182ce">**Focus on Form (FonF)**</span> | <span style="color:#3182ce">**Focus on Meaning**</span> |
|---|---|---|---|
| 접근 | Synthetic approach | Analytic approach | Analytic approach |
| 문법 선정 | pre-selected items | incidental (의미 활동 중 자연 발생) | 없음 |
| 맥락 | context-reduced, sentence level | context-embedded, discourse level | natural communication |
| 의사소통 역할 | secondary | primary | primary |
| 대표 교수법 | GTM, ALM | CR task, input enhancement | Natural Approach |

> Focus on Form: *"overtly draws students' attention to linguistic elements as they arise incidentally in lessons whose overriding focus is on meaning or communication."* (Long, 1991)

<span style="color:#c53030">**⚠️ 함정**: FonF ≠ FonFS. FonF는 의미 활동 **안에서** 형태에 주의를 기울이는 것. FonFS는 문법 항목을 **독립적으로, 순서대로** 가르치는 전통적 접근.</span>

<span style="color:#c53030">**2022.B.11**</span> — Focus on Form 관련 출제 확인

---

### Reactive vs Pre-emptive Focus on Form

FonF가 발생하는 **타이밍**에 따라 두 가지로 나뉜다.

- <span style="color:#3182ce">**Reactive FonF**</span>: 학습자가 오류를 범한 **후**, 교사가 corrective feedback을 제공. 의미 중심 활동 도중 즉각적으로 반응.
- <span style="color:#3182ce">**Pre-emptive FonF**</span>: 오류 발생 **전**, 문제가 예상되는 형태를 교사 또는 학습자가 미리 다룸.

더 큰 범주로 보면 **Planned FonF**(특정 항목을 사전에 결정 → intensive focus) vs **Incidental FonF**(즉흥적 발생 → extensive focus, reactive + pre-emptive 포함)로 나눌 수 있다.

---

### Explicit vs Implicit Instruction — Deductive vs Inductive

| | <span style="color:#3182ce">**Explicit Instruction**</span> | <span style="color:#3182ce">**Implicit Instruction**</span> |
|---|---|---|
| 목표 지식 | declarative knowledge (규칙 의식) | procedural knowledge (자동적 사용) |
| 대표 기법 | CR task, Garden Path | ALM, input flooding |
| 인지 부담 | 높음 (problem-solving) | 낮음 |

Explicit instruction 안에서 **Deductive vs Inductive** 구분이 추가로 나온다.

<span style="color:#3182ce">**Deductive approach**</span>: 규칙 먼저 → 예시와 연습. 장점: time-efficient. 단점: 덜 memorable.

<span style="color:#3182ce">**Inductive approach**</span>: L2 data → 학습자가 스스로 규칙 도출 (discovery learning / data-driven learning). 장점: memorable, promotes learner autonomy. 단점: time-consuming, 잘못된 규칙 가설 가능.

<span style="color:#c53030">**2025.B.11**</span> — discovery learning 관련 출제 확인

## ② 기출 맥락

### Input Enhancement — 출제 포인트

<span style="color:#c53030">**2024.A.2**</span> — Input Enhancement 출제 확인.

<span style="color:#3182ce">**Input Enhancement**</span>는 텍스트 안에서 목표 형태를 **typographic highlighting**(bold, underline, italics, 대문자화 등)으로 두드러지게 만들어 학습자의 주의를 유도하는 implicit FonF 기법이다.

> *"Input enhancement: draws learner attention to target forms through typographic highlighting techniques such as bolding, underlining, italicizing, or capitalizing the target form in authentic texts."*

핵심은 학습자가 **의미를 위해** 텍스트를 읽는 동안 형태도 함께 인식하게 된다는 것 — form 설명은 없다.

<span style="color:#c53030">**⚠️ 함정**: Input Enhancement = 강조 **있음** / Input Flood = 강조 **없음**. 둘 다 implicit이지만 highlighting 유무가 결정적 차이.</span>

---

### Focus on Form 유형 출제 패턴

임용에서 FonF 관련 문항은 주로 다음 두 가지를 묻는다:

① **개념 구분**: FonF vs FonFS의 특징 설명 중 맞는/틀린 것 고르기
② **기법 분류**: 특정 교실 상황을 제시하고 해당 기법(CR task, recast, input enhancement 등)이 무엇인지 묻기

답안 작성 패턴: *"(기법)은/는 (특징)하다는 점에서 (상위 범주)에 해당한다."*

## ③ 키텀 비교

### Input Enhancement vs Input Flood — 핵심 1개 차이

| | <span style="color:#3182ce">**Input Enhancement**</span> | <span style="color:#3182ce">**Input Flood**</span> |
|---|---|---|
| Typographic highlighting | ✅ 있음 (bold, underline 등) | ❌ 없음 |
| 목표 | form의 visual salience 증가 | 반복 노출로 자연스럽게 salience 증가 |
| 암묵성 | semi-implicit | fully implicit |

두 기법 모두 FonF 범주이며, 학습자에게 명시적 설명을 하지 않는다는 점에서 implicit 계열이다. 단 Input Enhancement는 텍스트 자체를 수정하므로 더 능동적인 개입이다.

---

### Corrective Feedback 6종 — Prompts vs Input-providing

임용에서 가장 자주 나오는 분류가 **6종 corrective feedback**이다. 두 그룹으로 나누면 암기가 쉽다.

**Input-providing** (교사가 correct form을 직접 제공):
- <span style="color:#3182ce">**Recast**</span>: implicit. 학습자 발화를 올바르게 reformulate하되 의미 초점 유지.
- <span style="color:#3182ce">**Explicit Correction**</span>: explicit. 오류를 명확히 지적하고 correct form 직접 제시.

**Prompts** (학습자가 스스로 self-repair하도록 유도):
- <span style="color:#319795">**Clarification Request**</span>: 이해 불가 신호 ("Pardon?", "What do you mean?")
- <span style="color:#319795">**Metalinguistic Feedback**</span>: 오류 유형을 metalinguistic comment/question/information으로 설명. correct form 직접 제공 안 함.
- <span style="color:#319795">**Elicitation**</span>: 미완성 문장·질문으로 correct form을 학습자가 생성하도록 유도.
- <span style="color:#319795">**Repetition**</span>: 학습자 오류 발화를 강조된 intonation으로 반복.

<span style="color:#dd6b20">**현직쌤 팁**: Prompt 4종은 모두 self-repair 기회 제공. Input-providing 2종은 self-repair 없음. 이 구분을 암기하면 6종 분류 문항 즉시 풀림.</span>

## ④ 수험 활용 팁

### Recast 함정 — "가장 효과적인 피드백"은 오답

<span style="color:#c53030">**⚠️ 빈출 함정**: Recast가 교실에서 가장 **빈번하게** 사용되는 것은 사실이지만, 가장 **효과적인** 피드백이라고 단정할 수 없다.</span>

Recast의 한계:
- Implicit하여 학습자가 교정으로 인식하지 못할 수 있음 (ambiguous)
- Uptake 비율이 prompt에 비해 낮음
- 학습자가 developmentally ready하지 않으면 효과 없음

Lyster(2004): Prompts가 recast보다 **successful uptake rate**가 높다.

---

### Uptake — 개념 정의와 분류

<span style="color:#3182ce">**Uptake**</span>: corrective feedback 직후 학습자가 보이는 **즉각적 반응**.

- <span style="color:#319795">**Repair (successful uptake)**</span>: correct form 산출
- <span style="color:#3182ce">**Needs Repair (unsuccessful uptake)**</span>: 반응은 했지만 오류 지속 / 단순 acknowledgment
- **No Uptake**: 아무 반응 없음

Uptake는 learner의 **noticing** + **pushed output**으로 기능하며, corrective feedback 효과의 지표로 본다.

---

### CR Task — 암기 포인트

<span style="color:#3182ce">**Consciousness-Raising Task**</span>의 특징 4개:
1. L2 data 제공 → 학습자 분석 → 자신의 언어로 규칙 언어화 → 교사 명시적 확인
2. **Explicit** 기법 → **declarative knowledge** 발달
3. Inductive 또는 deductive 방식 모두 가능
4. Meta-talk(언어에 대한 언어 사용) → 의미 있는 상호작용

<span style="color:#c53030">**⚠️ 함정**: CR task는 procedural knowledge를 기른다 → 오답. CR task = declarative knowledge.</span>

## ① 개념 정의 — 7개 영역을 영어 원문과 함께

### 1) Contrastive Analysis Hypothesis (CAH) & Transfer

> Contrastive Analysis Hypothesis proposes that differences between L1 and L2 are the primary source of errors in L2 acquisition. The strong version predicts errors before they occur by comparing L1 and L2 structures; the weak version analyzes errors after they occur to identify L1 influence.

<span style="color:#3182ce;">**CAH**</span>는 L1과 L2 사이의 차이가 L2 습득에서 오류의 주요 원인이라고 본다. 두 버전이 있고 시험에서 반드시 구분해야 한다:

| 버전 | 시점 | 초점 |
|---|---|---|
| <span style="color:#3182ce;">**Strong version**</span> | <span style="color:#319795;">오류 발생 **전** 예측</span> | L1–L2 대조 분석 → 어려운 항목 중심 교수 |
| <span style="color:#3182ce;">**Weak version**</span> | <span style="color:#c53030;">오류 발생 **후** 분석</span> | cross-linguistic influence 확인 |

transfer의 방향에 따른 유형:

- <span style="color:#3182ce;">**Positive transfer**</span>: L1이 L2 학습을 facilitate
- <span style="color:#3182ce;">**Negative transfer**</span>: L1이 L2를 interfere
  - <span style="color:#3182ce;">**Interference**</span> = **interlingual** transfer (L1 규칙 → L2에 잘못 적용) e.g. "see an exam"
  - <span style="color:#3182ce;">**Overgeneralization**</span> = **intralingual** transfer (L2 규칙을 L2 내에서 과잉 일반화) e.g. "I goed"
- <span style="color:#3182ce;">**Avoidance**</span>: L1에 **없는** 구조를 TL에서 사용하지 않는 것
- <span style="color:#3182ce;">**Overuse**</span>: L1에 **있는** 표현을 TL에서 부자연스럽게 과용하는 것

> 💡 <span style="color:#dd6b20;">**현직쌤 팁**</span>: Interference와 Overgeneralization의 방향은 답안에서 반드시 명시해야 한다. "interlingual transfer (L1 → L2)"와 "intralingual transfer (within L2)"를 각각 정확히 써야 만점.

### 2) Interlanguage ⭐⭐

> Interlanguage is an intermediate linguistic system constructed by L2 learners that is distinct from both L1 and the target language. It is systematic, variable, and dynamic — characterized by its own unique, coherent rule system.

<span style="color:#805ad5;">**Selinker**</span>의 <span style="color:#3182ce;">**Interlanguage**</span>는 L2 학습자가 구성하는 중간 언어 체계로, L1과 TL 모두와 다르다. 세 가지 핵심 특징:

- <span style="color:#319795;">**Systematic**</span>: 학습자 자신만의 일관된 rule system
- <span style="color:#319795;">**Variable**</span>: 맥락에 따라 달라짐
- <span style="color:#319795;">**Dynamic**</span>: 시간이 지남에 따라 발달

**발달 단계 4단계** (<span style="color:#c53030;">★★★ 최빈출</span>):

| 단계 | 특징 | Self-correction |
|---|---|---|
| <span style="color:#3182ce;">**Presystematic**</span> | random errors · 규칙 인식 희미 | ❌ |
| <span style="color:#3182ce;">**Emergent**</span> | 일부 일관성 · <span style="color:#c53030;">backsliding</span> · uptake ❌ | ❌ (피드백 줘도 X) |
| <span style="color:#3182ce;">**Systematic**</span> | 일관적 · uptake ✅ | ✅ (피드백 있을 때) |
| <span style="color:#3182ce;">**Stabilization**</span> | 오류 거의 없음 · fossilization 위험 | ✅ (피드백 없어도) |

- <span style="color:#3182ce;">**Backsliding**</span>: Emergent 단계에서 규칙을 이해한 것 같지만 이전 단계로 퇴행하는 현상
- <span style="color:#3182ce;">**Restructuring**</span>: interlanguage 발달 과정에서의 질적 변화

**Fossilization**:

> Fossilization is a relatively permanent incorporation of incorrect linguistic forms into the learner's L2 competence. It is caused by lack of negative feedback, insensitivity to feedback, or excessive automatization.

<span style="color:#3182ce;">**Fossilization**</span>은 잘못된 언어 형식이 **상대적으로 영구적**으로 굳어지는 현상이다. 예방을 위해 <span style="color:#319795;">explicit corrective feedback</span>으로 오류 인식을 유도해야 한다.

(<span style="color:#c53030;">**2010 Q21 기출**</span>: 중간 언어 화석화 현상 / <span style="color:#c53030;">**2023 A-1 기출**</span>: backsliding, U-shaped development, overgeneralization, fossilization)

**U-shaped Learning**:

Phase 1(correct: imitation/lexical item) → Phase 2(incorrect: overgeneralization) → Phase 3(correct: rule internalized)

e.g. went → **goed** → went

(<span style="color:#c53030;">**2023 A-1 기출**</span>)

### 3) Error Types

**Source of Error 4가지** (<span style="color:#c53030;">★★★ 구분 필수</span>):

| Source | Type | 예시 |
|---|---|---|
| <span style="color:#3182ce;">**Interference**</span> | Interlingual (L1→L2) | 'see an exam', 'do a shower' |
| <span style="color:#3182ce;">**Overgeneralization**</span> | Intralingual (L2 내) | 'I goed', 'She cried-ed' |
| <span style="color:#3182ce;">**Induced error**</span> | Context of learning | 교사의 잘못된 설명, 교재 오류 |
| Communication-based | Communication strategies | 'airball' for 'balloon' |

**Error Classification**:

- <span style="color:#3182ce;">**Global error**</span>: communication을 **hinder** → 반드시 교정
- <span style="color:#3182ce;">**Local error**</span>: message는 전달 → 반드시 교정할 필요 없음
- <span style="color:#3182ce;">**Overt error**</span>: sentence level에서 명백히 비문법적
- <span style="color:#3182ce;">**Covert error**</span>: grammatically well-formed이지만 discourse level에서 해석 불가

**교정 범위** (학습 목표에 따라):
- Fluency 목표 → global error만 교정
- Accuracy 목표 → global + local 모두 교정 (fossilization 예방)

### 4) Corrective Feedback Types ⭐⭐⭐

> Corrective feedback refers to any teacher response that draws attention to learner error. Types range from implicit (maintaining communicative flow) to explicit (directly indicating error).

<span style="color:#3182ce;">**Corrective feedback**</span>는 implicit과 explicit으로 구분된다.

| Type | 구분 | 특징 | 예시 |
|---|---|---|---|
| <span style="color:#3182ce;">**Recast**</span> | **Implicit** | erroneous utterance 재구성 · flow 유지 · positive+negative evidence · 학습자가 confirmation으로 오해 가능 | S: "I goed." / T: "Oh, you **went**?" |
| <span style="color:#3182ce;">**Clarification request**</span> | Implicit | self-repair 유도 · communication breakdown 가능 · 가장 효과적 | "I'm sorry?" / "Pardon?" |
| <span style="color:#3182ce;">**Metalinguistic feedback**</span> | Implicit/Explicit | 오류 성격 설명 · **correct form 제공 X** | "What is the past tense?" |
| <span style="color:#3182ce;">**Elicitation**</span> | Implicit/Explicit | incomplete sentence → **self-correct 유도** | "He comes... / We are...?" |
| Explicit correction | Explicit | 오류 직접 명시 + correct form 제공 | "No, not 'goed', say 'went'." |
| Repetition | Implicit | 오류 부분만 반복 · intonation 변화 | T: "**Goed**?" |

**Recast 핵심 4가지** (<span style="color:#c53030;">★★★</span>):
1. <span style="color:#319795;">Implicit</span> · communicative flow **유지**
2. <span style="color:#319795;">Positive evidence</span>(correct form) + <span style="color:#319795;">Negative evidence</span>(오류 암시) 동시 포함
3. 학습자가 <span style="color:#c53030;">confirmation check</span>로 오해 가능 → unsuccessful uptake
4. Meaning에 집중하느라 form 수정 인식 못할 수 있음

(<span style="color:#c53030;">**2012 Q22 기출**</span>: 오류 수정 유형 구분 / <span style="color:#c53030;">**2014_A 기입9 기출**</span>: corrective feedback, recast, explicit correction / <span style="color:#c53030;">**2015_A 기입7 기출**</span>: recast, metalinguistic feedback / <span style="color:#c53030;">**2016_B 서술5 기출**</span>: recasts, prompts 비교 / <span style="color:#c53030;">**2020_A 서술1 기출**</span>: metalinguistic feedback)

**Sociocultural 관점의 CF**:
- CF = <span style="color:#319795;">other-regulation</span> → learner가 <span style="color:#319795;">self-regulation</span> 달성하도록 지원
- CF는 <span style="color:#319795;">step by step as scaffolding</span>으로 제공
- ZPD 내에서 작동

### 5) Uptake · Modified Output · Pushed Output ⭐⭐

> Uptake refers to any learner utterance that immediately follows the teacher's corrective feedback, regardless of whether the error has been successfully repaired.

| 개념 | 정의 | 핵심 |
|---|---|---|
| <span style="color:#3182ce;">**Uptake**</span> | T's corrective feedback에 **즉각 뒤따르는** 학습자 발화 | successful / unsuccessful / no uptake |
| <span style="color:#3182ce;">**Modified output**</span> | 피드백 이후 수정이 **실제로 이루어졌는지** 여부 | 수정 결과 focus |
| <span style="color:#3182ce;">**Pushed output**</span> | T가 학습자를 올바른 형태로 **push**하는 과정 | not all pushed = modified |

3개념 구분 공식:
- Uptake = feedback 직후 **즉각 반응** (수정 여부 무관)
- Modified output = 수정 **결과**에 focus
- Pushed output = T가 push하는 **과정** → 반드시 modified output인 것은 아님

**Positive vs Negative Evidence**:
- <span style="color:#319795;">**Positive evidence**</span>: model of correct form
- <span style="color:#319795;">**Negative evidence**</span>: corrective feedback (pre-emptive / reactive, explicit / implicit)

### 6) Modified Input

> Modified input refers to the linguistic simplification or elaboration that native speakers or teachers use when speaking to non-proficient language users.

| 유형 | 화자 | 대상 |
|---|---|---|
| Care-taker talk | parents/babysitters | 어린 아이 |
| <span style="color:#3182ce;">**Foreigner talk**</span> | **native speakers** | 외국인 일반 |
| <span style="color:#3182ce;">**Teacher talk**</span> | **교사** | classroom 학습자 |

(<span style="color:#c53030;">**2021_A Q10 기출**</span>: foreigner talk, input modification, interaction)

**Input Modification 유형 3가지**:
- <span style="color:#3182ce;">**Simplification**</span>: complex → simple form (어휘·문법 교체)
- <span style="color:#3182ce;">**Elaboration**</span>: restate/repeat differently (<span style="color:#319795;">positive effect on SLA</span>)
- <span style="color:#3182ce;">**Regularization**</span>: 더 basic/explicit 형태 선택

(<span style="color:#c53030;">**2019_A 서술1 기출**</span>: interaction, negotiation of meaning, modified input)

> 💡 <span style="color:#dd6b20;">**현직쌤 팁**</span>: Simplification과 Elaboration의 정의 swap이 시험에 자주 나온다. Elaboration은 어휘를 교체하는 게 아니라 **같은 내용을 다른 방식으로 재진술**하는 것임을 명심.

### 7) Display Q · Referential Q · IRE · IRF ⭐⭐⭐

> A display question is one to which the questioner already knows the answer, used to check learners' knowledge. A referential question is one where the questioner does not know the answer, thus promoting authentic communication.

| 유형 | 특징 |
|---|---|
| <span style="color:#3182ce;">**Display question**</span> | T **already knows** the answer · 이해도 확인 · e.g. "What is the past tense of go?" |
| <span style="color:#3182ce;">**Referential question**</span> | T does **NOT know** the answer · authentic communication 촉진 · e.g. "What did you do last weekend?" |

**IRE vs IRF**:

| 패턴 | 구조 | 특징 |
|---|---|---|
| <span style="color:#3182ce;">**IRE**</span> (Initiation–Response–Evaluation) | T initiates → S responds → T **evaluates** | display question 중심 · teacher-centered |
| <span style="color:#3182ce;">**IRF**</span> (Initiation–Response–Feedback) | T initiates → S responds → T **gives feedback** | referential question 가능 · authentic interaction |

## ③ 헷갈리는 key terms 비교

### Interference vs Overgeneralization

| | Interference | Overgeneralization |
|---|---|---|
| 방향 | <span style="color:#c53030;">L1 → L2</span> (interlingual) | <span style="color:#c53030;">L2 내부</span> (intralingual) |
| 원인 | L1 규칙 잘못 적용 | L2 규칙 과잉 일반화 |
| 예시 | "see an exam" | "I goed" |

### Avoidance vs Overuse

| | Avoidance | Overuse |
|---|---|---|
| 조건 | L1에 **없는** 구조 | L1에 **있는** 표현 |
| 행동 | TL에서 **회피** | TL에서 **부자연스럽게 과용** |

### Strong vs Weak CAH

| | Strong version | Weak version |
|---|---|---|
| 시점 | 오류 <span style="color:#319795;">발생 전 예측</span> | 오류 <span style="color:#c53030;">발생 후 분석</span> |
| 방법 | L1–L2 대조 → 어려운 항목 교수 | cross-linguistic influence 파악 |
| 한계 | L1 오류만 설명 가능 | L1, L2 오류 모두 설명 가능 |

### Recast vs Explicit Correction

| | Recast | Explicit Correction |
|---|---|---|
| 구분 | <span style="color:#319795;">Implicit</span> | <span style="color:#c53030;">Explicit</span> |
| Flow | <span style="color:#319795;">유지</span> | <span style="color:#c53030;">끊김</span> |
| Evidence | positive + negative 동시 | 직접 오류 지적 + correct form |
| 위험 | 학습자가 confirmation으로 오해 | — |

### Metalinguistic Feedback vs Elicitation

| | Metalinguistic Feedback | Elicitation |
|---|---|---|
| 방식 | 오류 성격 **설명** | incomplete sentence/question |
| Correct form | <span style="color:#c53030;">제공 X</span> | 학습자가 self-correct하도록 유도 |
| 예시 | "What is the past tense?" | "He comes... / We are...?" |

### Display Q vs Referential Q

| | Display Question | Referential Question |
|---|---|---|
| 교사 | <span style="color:#c53030;">이미 답을 앎</span> | <span style="color:#319795;">답을 모름</span> |
| 목적 | 이해도 확인 | authentic communication 촉진 |
| 패턴 | IRE 중심 | IRF 가능 |

### Global vs Local Error

| | Global Error | Local Error |
|---|---|---|
| 의사소통 | <span style="color:#c53030;">hinder communication</span> | message 전달 가능 |
| 교정 | 반드시 교정 | 교정 필수 아님 |

## ④ 합격자 노트 기반 답안 작성 팁

### 함정 1: Interference를 intralingual로 쓰기

<span style="color:#c53030;">**Interference = interlingual transfer (L1 → L2)**</span>. Overgeneralization이 intralingual(L2 내부). 둘을 뒤집으면 즉시 감점.

### 함정 2: Recast를 explicit으로 분류하기

Recast는 <span style="color:#c53030;">**implicit**</span>이다. "explicitly signals error"라는 선지가 있으면 × . communicative flow를 유지하면서 erroneous utterance를 재구성하는 게 recast의 정의.

### 함정 3: Metalinguistic feedback이 correct form을 제공한다고 쓰기

<span style="color:#c53030;">**Metalinguistic feedback은 correct form을 직접 제공하지 않는다.**</span> 오류의 성격을 설명하거나 질문하는 것. "What tense should this be?"처럼. Explicit correction만 correct form을 제공한다.

### 함정 4: Emergent stage에서 self-correction 가능하다고 쓰기

Emergent stage는 <span style="color:#c53030;">**self-correction 불가**</span>. Backsliding이 일어나는 단계. Systematic stage부터 피드백을 주면 self-correct 가능하고, Stabilization stage에서는 피드백 없이도 가능.

### 함정 5: Display Q와 Referential Q 방향 혼동

Display Q = 교사가 이미 <span style="color:#c53030;">**답을 아는**</span> 질문. Referential Q = 교사도 <span style="color:#c53030;">**답을 모르는**</span> 진짜 정보 요청. 거꾸로 쓰면 즉시 감점.

### 답안 시작 패턴

- ❌ "In this passage, the teacher uses..."
- ✅ "The teacher's feedback is an example of [type] in that ..."
- ✅ "The error in (A) is a case of [interference/overgeneralization] because ..."
- ✅ "[Stage] is characterized by [feature], which means ..."

> 💡 <span style="color:#dd6b20;">**현직쌤 팁**</span>: Ch.2는 답안에서 **학습자 발화의 예시를 그대로 인용**하고 그 오류가 어떤 유형인지 연결하는 패턴이 많다. "Student's utterance 'I goed' shows overgeneralization — an intralingual transfer within L2 — since ..."처럼 예시 인용 → 유형 명시 → 근거 설명 3단계로 쓰는 것이 합격자 패턴.
